## 重生成 dark 模式 splash 源图（splash_dark_500/12）

时间：2026-08-18 20:04 CST

现象：现有 `assets/images/splash_dark_500.png` / `splash_dark_12.png` 的
萝卜叶子是早期未清理草稿（4 片叶子相互交叉成乱线），整体看起来像草稿。

根因：旧 splash 是从更早版本的图标导出的；当前源 SVG
`assets/images/icon-round-simple-chip.svg` 的注释明确说叶子已"合并成
单一外轮廓 (fill none, stroke currentColor) so no internal crossing lines
appear between them"，但旧 PNG 仍沿用早期路径数据。

改动：
- 新增 `scripts/gen_splash_dark.py`：从 `icon-round-simple-chip.svg` 重新
  生成 dark 模式 splash 源图（与 `gen_splash.py` 对称，文件名带 `_dark`）。
  - 渲染器选用 `resvg-py`（Rust resvg），因为 `cairosvg 2.9.0` 对本 SVG
    的 `<mask>` 挖空支持有缺陷（会把整个圆角方块错误填成实心）。
  - 注入 `style="color:#fff"` 让 `currentColor` 解析为白色（搭配
    `flutter_native_splash.yaml` 中 `color_dark: "#000000"` = 纯黑底）。
  - 画布与几何与 `gen_splash.py` 对称：500 源图 1024×1024，12 源图
    576×576、主体直径 334。
- 重新生成两份透明 RGBA PNG：
  - `assets/images/splash_dark_500.png`（1024×1024）
  - `assets/images/splash_dark_12.png`（576×576，主体直径≈334）
- 原文件备份到 `temp/backups/splash_dark_{500,12}.png.bak-20260818-2004`。

设计变更说明：源 SVG 是**填充式 chip**（白色圆角方块 + 挖空的"纸"窗口），
与旧 splash 的纯线条风格不同。这是 SVG 本身的 chip 变体设计；如需保留
纯线条风格只清理乱线，可改用 `icon-round-simple.svg` 重出。

用法（下次换图标后重跑）：
```
python scripts/gen_splash_dark.py
dart run flutter_native_splash:create
```

## fromSeed 反推 seed 可行性测试（主题色调研）

背景：用户希望 primary 直接等于奶油色 `#FBDD82`，并假设 Material `ColorScheme.fromSeed` 可逆（给 primary 反推 seed）。

结论（已由 `test/reverse_seed_test.dart` 用真实 `ColorScheme.fromSeed` 验证）：
- tonalSpot（默认 variant）下，primary **只继承 seed 的 hue**；
- primary 的 **chroma 被算法固定 ≈36**（`scheme_tonal_spot.dart:29` 写死 `TonalPalette.of(hue, 36.0)`），与 seed chroma 无关；
- primary 的 **tone 被算法固定为 40（亮）/ 80（暗）**（`material_dynamic_colors.dart:245`），任何 DynamicSchemeVariant 都改不了。
- 因此 "primary = 奶油色（tone≈87）" 在数学上不可能通过 fromSeed 得到；fromSeed 对 primary **只有 hue 一维可逆**。
- 要让主色真的是奶油，必须 `ColorScheme.fromSeed(...).copyWith(primary: cream, onPrimary: 深色)` 直接覆盖。

测试运行结果（关键数值）：
- cream seed `0xFFFBDD82` → primary `hue≈93.6, chroma≈36, tone≈39.9` → `#ff715c0c`（深橄榄）
- 同 hue、不同 chroma 的 seed → primary hue 完全一致（证明 chroma 无关）
- 反推 seed → 仍得到 tone≈40 的深橄榄，≠ 奶油
- 遍历 360° hue：最接近奶油的 primary 归一化距离²=0.539，luminance=0.113（奶油≈0.78），证明永远到不了亮色

改动文件：
- 新增 `test/reverse_seed_test.dart`
- `pubspec.yaml` dev_dependencies 增加 `material_color_utilities: ^0.13.0`（仅测试用，不影响发布产物）；已 `flutter pub get`。
