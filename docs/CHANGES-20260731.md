- **P0-1 重建路径跳过 GC**：远端 manifest 为空（`remoteManifest == null`）或 header 解析 `FormatException`（损坏重建分支）时不调用末尾 `_gcOrphanBlobs`，避免误删其它设备的 blob。
- **P0-3 repairRemote blob 缺失兜底**：`repairRemote` 中 `blob == null` 时，若本机 `database.readNoteByUuid` / `readNoteByContentHash` 有明文（含孪生笔记），则 `_uploadNote` 重传补回并标记 `SyncActionType.heal`；无明文则记为 `failedNoteUuids`（绝不静默丢失）。
- **P0-4 普通下载 blob 缺失兜底**：下载路径 `envelope == null` 时，若本地有未删除且 `contentHash` 匹配的明文（含孪生查 `readNoteByContentHash`），则 `_uploadNote` 自愈补传并返回 `_DownloadHealed`；否则返回 `_DownloadFailed` 进入 `failedNoteUuids`。

### P1 修复（备份 / 隔离）

- **P1-1 manifest 代际环形备份**：`backupManifest([Uint8List?])` 接口落地——三后端一致把"即将被覆盖的旧 manifest 密文"写入后端侧 `manifest-backup/` 子目录的环形备份（`manifest.bak-0..4`，轮转槽位记 `.manifest-bak-index`）。LocalFS 落 vault 目录、SafeServer/WebDAV 落各自后端子目录，**统一不再写客户端临时目录**。
- **P1-2 GC 软删除隔离区**：`_gcOrphanBlobs` 改为 `deleteBlobSoft`（进 `blo-orphan/` 隔离区），循环结束调用 `purgeOrphans(_orphanRetention=30d)` 才真正物理删除，给一切误判留后悔药。
  - LocalFS：`rename` 到 `blobs-orphan/<hash>.<epochMs>`。
  - WebDAV：`COPY` + `DELETE` 到 `blobs-orphan/`。
  - SafeServer：v2.2 资源层 `move` 到 `blobs-orphan/`（`_resourceMove`），并保留旧服务端 `GET+PUT(0rphan-)+DELETE` 降级路径。

### 接口与抽象

- `SyncBackend` 新增带默认实现的接口方法：`deleteBlobSoft` / `listOrphanBlobs` / `purgeOrphans` / `backupManifest`（默认 no-op，子类按需覆盖）。
- 环形份数常量 `kManifestBackupRingCount = 5` 提到共享模块 `sync_backend.dart` 统一定义并导出，避免三后端重复定义。
