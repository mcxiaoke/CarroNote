# 2026-10-11 变更记录

## 2026-10-11 11:45:00 — feat(deps): 升级 file_picker 至 13.1.0 并彻底移除 Android Gradle Hack

### 需求与背景

- **移除 build.gradle 兼容 Hack**：上一轮升级 AGP 9.4.1 时，`file_picker 11.x` 内部逻辑粗暴判断 `isAgp9OrAbove` 而直接跳过应用 Kotlin 插件，因此在 `android/build.gradle` 中临时做了补丁注入。
- **现代化无侵入方案**：将 `file_picker` 升级到官方已修复该问题的版本（`13.1.0` + `android_file_picker 2.0.1` 原生支持判断 `android.builtInKotlin`），彻底解耦自定义 Gradle hack。

### 核心改动

1. **依赖升级与协同包对齐**：
   - `pubspec.yaml`：升级 `file_picker` 至 `^13.1.0`。
   - 同步升级 `device_info_plus: ^13.3.0` 与 `share_plus: ^13.3.1`，解决 Windows 平台下 `win32 ^6.x` 的依赖冲突约束。
2. **源码破坏性接口适配**：
   - `lib/models/file_handler.dart`：适配 13.x API 调整，单选由 `FilePicker.pickFiles(allowMultiple: false)` 改用更规范的 `FilePicker.pickFile()`；将已废弃的 `file.size` 获取调整为直接通过文件系统 `file.lengthSync()` 获取。
   - `lib/dialogs/export_backup_dialog.dart`：适配 `FilePicker.saveFile` 传入 `bytes: Uint8List(0)` 并在桌面端接收 `Uri?` 转路径。
   - `test/utils/device_id_test.dart`：适配 `device_info_plus 13.x` 的 `AndroidDeviceInfo` 模型新增的不可空 `time` 时间戳字段。
3. **Gradle 架构清理与 AGP 9 产物路径规范化**：
   - `android/build.gradle`：彻底删除此前在 `subprojects` 针对 `file_picker` 注入 `org.jetbrains.kotlin.android` 的临时 Hack。
   - 将 `subprojects` 的 `buildDirectory` 重定向与 `evaluationDependsOn(':app')` 拆解为两个独立的 pass，遵循 Flutter 官方模板规范，避免了在插件子项目提前触发 `:app` 评估导致 AGP 9 的 `minifyReleaseWithR8` 检索 `proguard-android-optimize.txt` 产生旧路径不匹配的问题。

### 验证

- `flutter analyze`：0 issues，无告警与报错。
- `dart test packages\core\test`：全部测试通过。
- `flutter test`：248 个测试全部通过。
- `flutter build apk --release`：成功生成 `app-release.apk` (82.6MB)，且完全不需要任何 Gradle hack。
- `flutter build windows --debug`：成功生成 `CarroNote.exe`，桌面端与移动端构建双向稳定。

## 2026-10-11 10:12:30 — build(android): 升级 Android 构建工具链至 AGP 9.4.1 与 Gradle 9.6.0

### 需求与背景

- **消除 SDK XML 版本兼容警告**：此前在执行 `flutter build apk` 时，Android SDK 解析层报 `Warning: SDK processing. This version only understands SDK XML versions up to 3 but an SDK XML file of version 4 was encountered`。
- **现代化构建工具链对齐**：参考 `CarroMed` 项目的构建配置，将 Gradle 及 Android Gradle Plugin (AGP) 升级到最新的稳定工具链版本，并解决由此带来的多插件 Kotlin 编译与 Windows 文件锁定问题。

### 核心改动

1. **Gradle Wrapper 升级**：
   - `android/gradle/wrapper/gradle-wrapper.properties`：升级 `distributionUrl` 至 `gradle-9.6.0-bin.zip`（腾讯云镜像），并配置发行包 SHA256 完整性校验哈希。
2. **AGP 与 Maven 仓库镜像配置**：
   - `android/settings.gradle`：`com.android.application` 由 `8.11.1` 升级至 `9.4.1`；`pluginManagement.repositories` 补充阿里云 Google/Public/Gradle-Plugin 镜像源加速依赖拉取。
   - `android/build.gradle`：`allprojects.repositories` 补充阿里云 Maven 镜像。
3. **gradle.properties 优化**：
   - `android/gradle.properties`：移除已废弃的 `android.enableJetifier=true`；添加 `android.nonTransitiveRClass=true`；添加 `android.sync.suppressAgpWarnings`；保留 `android.builtInKotlin=false` 与 `android.newDsl=false` 确保 Flutter 旧版插件桥接正常。
4. **插件与 Windows 构建兼容适配**：
   - `android/build.gradle`：在 `subprojects` 中针对 `file_picker` 补全 `org.jetbrains.kotlin.android` 插件注入（解决该插件在 AGP 9 环境下因误判 `builtInKotlin` 导致 Kotlin 代码未编译的缺失符号错误）；同时禁用子模块的 `lintVital` 任务，避免在 Windows 多模块并发构建时触发 `intermediates\lint-cache` 文件占用锁定异常。
   - `android/app/build.gradle`：在 `android` 块配置 `lint { checkReleaseBuilds false; abortOnError false }`。
