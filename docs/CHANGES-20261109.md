## 2026-11-09 15:40:00 — fix(test): 修复集成测试 ErrorWidget.builder 全局状态变动导致的大范围失败

### 背景与根因定位
- **问题现象**：执行 `flutter test integration_test/app_test.dart -d windows` 时所有用例批量崩溃报错：`The value of ErrorWidget.builder was changed by the test`。
- **根因分析**：
  1. Flutter 3.2x / 现代版本 Flutter 中，`IntegrationTestWidgetsFlutterBinding` 严格继承并统一了 `TestWidgetsFlutterBinding` 针对全局环境干净度的断言检查 `_verifyErrorWidgetBuilderUnset`。
  2. 原 `lib/main.dart` 中的 `ErrorWidget.builder = ...` 无条件全局覆盖，该定制原意是「避免 release 模式静默灰屏卡死」。当测试框架启动应用时，这一覆盖篡改了测试框架的默认错误 Widget 构建器，触发绑定框架的断言失败。
- **解决方案与修复**：
  1. `lib/main.dart`：将 `ErrorWidget.builder` 的自定义渲染逻辑限制在 `if (kReleaseMode)` 下执行，在 debug/test 环境下保留 Flutter 默认的错误边界与测试断言机制。
  2. `integration_test/app_test.dart`：在 `_hubTileKeys` 列表中补充新增的代理设置项 `'ui-setting-hub-proxy'`，确保遍历设置页子页面测试能够完整覆盖并验证代理设置页无溢出与崩溃。
  3. `test/utils/device_id_test.dart`：修复 `// ignore: depend_on_referenced_packages` 忽略指令行位置偏差，消除 `flutter analyze` 报告的平台包依赖警告。
- **验证结果**：
  - `flutter analyze`：通过（0 issues found）。
  - `dart test packages/core/test`：全部通过（448 passed, 0 failed）。
  - `flutter test`：全部通过（269 passed, 0 failed）。
  - `flutter test integration_test/app_test.dart -d windows`（含多视口遍历与同步流测试）：全部通过通过。

## 2026-11-09 13:16:56 — feat(network): 独立全局网络代理设置与同步服务自动接入

### 背景与改动
- **设计文档**：已创建并归档至 `docs/feature-network-proxy-design.md`。
- **设置主页解耦**：在 `SettingsScreen` 中新增独立的「网络 / Network」分组与「网络代理 / Network Proxy」导航项，与具体的同步后端凭据表单完全解耦。
- **全局代理管理 (`ProxyConfig`)**：新增 `lib/data/proxy_config.dart`，统一管理网络代理开关与地址持久化；提供日志脱敏 (`redactProxyForLog`) 与连通性探测 (`testConnectivity`)。
- **跨平台 HTTP Client 工厂**：在 `lib/src/platform/` 中引入 `http_client_factory.dart`（原生端使用 `dart:io` `HttpClient.findProxy` 转换为标准 PAC 规则，Web 端条件导出优雅降级）。
- **同步服务自动接入**：`SyncBackendDraft.buildBackend()` 统一使用 `ProxyConfig.createHttpClient()` 自动为 `WebDavBackend` 和 `SafeServerBackend` 注入已配置代理的底层客户端。
- **配置变更热重载**：在代理设置页保存后，自动通知已初始化的 `SyncService` 热切换后端实例，无需重启应用。
- **国际化与测试**：完善 `zh-CN.json` 和 `en-US.json` 翻译；新增 `test/data/proxy_config_test.dart`，并通过全量核心测试与 Windows Debug 编译验证。
