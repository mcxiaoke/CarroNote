## 2026-08-27 M1 解密失败容错（docs/RELEASE-REVIEW-20260826.md 中风险）

此前任何一行解密失败都会让整个查询抛异常（readAllNotes/回收站/同步全不可用，
乃至整库"不可读"，提示仅一次性 toast）。M1 按阈值区分两类失败，由既有自愈机制
（云端 blob 拉回 / 每日备份）兜底：

- **单行/少数**（未达阈值 `broken >= 10 || (broken >= 3 && broken*10 >= total)
  || broken == total`）：**原始删除**该行（不进 purgedUuids，云端可拉回恢复），
  其余健康行正常返回；删除包事务避免崩溃半删，并同步移除缓存条目。
- **系统性故障**（密码错误 / 整库损坏）：抛 `MassDecryptionFailureException`，
  **一行不删**，UI 全屏阻塞错误态（重试 / 返回登录，仅清内存密钥不动库）。
- `broken == total` 覆盖超小库（1/1、2/2）全损——全损必为系统性，防错误 key 下
  被误判为隔离损坏而悄悄删光后"成功"。

实现要点（`database_handler.dart`）：
- 阈值判定 `_isMassDecryptionFailure`、批量守卫 `_decryptRowsWithGuard`（全量/
  回收站/待同步/缓存重建）、单行守卫 `_decryptRowWithGuard`（readNote*：失败删除
  返回 null）、删除函数 `_deleteBrokenRows`。
- **迁移路径严格化**：`reEncryptAllNotes*` 改用 `_readAllNotesStrict`（全成或全败，
  失败即抛 SyncDecryptionException 回滚）——避免小库错误 oldKey 被误删。
- `setDataKey` 加 `_invalidateCache()`（错误 dataKey 命中缓存会绕过守卫）。

UI 层：
- `home.dart`：`refreshNotes` 捕获 mass 置全屏阻塞错误态；`didPopNext` 统一走
  `refreshNotes`。
- `deleted_notes.dart`：`_refresh` 包 try/catch，mass/异常清空 + toast，不再卡 loading。
- `change_passphrase.dart`：改密码前检查捕获 mass → 阻止改密码。

设计取舍：不保留隔离落盘（broken_notes）——其取证恢复链覆盖的三重低概率场景
已有自愈机制兜底，性价比低；exportAll 维持保护性抛异常；sync_engine 内 mass 传播
中断同步（系统性失败本就不该继续同步）。

配套：`m1_decrypt_failure_test.dart`（含全损/单行/缓存一致性 8 用例）、
`database_migration_rollback_test.dart` 更新。
