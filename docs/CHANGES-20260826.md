### N-3 logout/dispose 与在途同步互斥（P1）

`await waitForSyncCompletion()` 再关 journal/backend；sync()/repairRemote()/
autoSync()/switchBackend() 均拒绝在关闭中启动。logout 完成后复位 `_closing`
（服务保留复用）。消除 inactivity 超时登出在 `engine.sync()` 中途关闭
backend/journal 的水位竞态。

### T-6 WebDAV ETag 探测结果参与决策展示（P1）
诊断快照新增 `etagSupported` 字段（仅 WebDAV 后端有值），诊断页 Backend
Config 段在不支持时标红提示"并发编辑可能互相覆盖"，可读文本同步输出。
未做一刀切拒绝同步（避免破坏坚果云等非标但可用的后端），严格化留待回归测试补充后决策。

### T-25 exportAll 导出墓碑（P1）
`DatabaseHandler.exportAll()` 改用 `readAllNotesIncludingDeleted()`，
备份-恢复循环保留删除状态；导入侧 `SafeNote.fromJson` 完整还原 deleted
字段，UI 列表按 deleted 过滤不受影响。

### N-5 应用退出链路接入 SyncService.dispose（P2）
main.dart `_shutdown()` 在停日志 WebServer 后、关日志文件前调用
`SyncService.instance.dispose()`（异常不阻断退出），journal 内存缓冲退出前 flush。

### N-7 autoSync 尊重自动同步开关（P2）
`autoSync()` 增加 `isAutoSyncEnabled` 守卫：关闭自动同步后笔记变更/回前台
不再被动发起远端同步。登录、设置页启用开关/保存配置三处显式用户动作改走
`sync()` 不受该开关约束。

### N-9 收尾 改密码并发互斥（P2）
`Keyring.changePassword` 拆分为静态 Future 链串行队列（`_enqueueLedgerWrite`）
+ 原子化实现 `_changePasswordLocked`：并发改密码不再 last-writer-wins，
后到者在先到者 persist 后的乐观校验中中止；`database.isMigrating` 时直接拒绝。

### N-10 收尾 解密异常分流（P2）
`SyncDecryptionException` 新增 `isTagError` 标志（wrapDecryptionError 注入）；
keyring `_unwrapOrThrow` 仅对 GCM 认证失败抛 WrongPasswordException，
信封长度不足等结构性解密异常归为 KeyringCorruptedException，不再误报"密码错误"。

### T-22 getTextDirecton → getTextDirection（P3）
定义 + note_widget/note_card_body/search_widget 共 8 处重命名。

### T-23 BackendUnavailableException 增加 retryable（P3）
新增 `retryable` 字段（默认 true）与 `.http(what, statusCode, detail)` 工厂
（401/403 自动置 false）；WebDAV/SafeServer 两后端全部状态码抛出点与显式
401 分支已接入；引擎 `_withBlobRetry` 遇不可重试异常立即放弃，
uploadNote 的 NetworkError.retryable 跟随异常语义。

### T-24 缓存重建竞态防护（P3）

## 2026-08-26 15:01 note_meta 同步 review 整改（M-1 / L-1 / L-2 + Nits）

外部 review 三条主问题全部实锤并修复：

### M-1 `_metaCache` 脏标记滞后
`markNoteMetasSynced` 此前仅 Batch 更新 DB，缓存 entry 的 synced 滞后为 false。
已补缓存刷新：条件与 DB 对齐（`updatedAt == 快照值`），防覆盖上传期间并发改动；
墓碑行不在缓存中自然跳过。**注意**：原测试因"缓存未建"巧合通过——已重写用例，
显式先 `readAllNoteMeta()` 建缓存再断言（getNoteMeta 走缓存命中路径），
锁住修复行为。

### L-1 skip-PUT 路径不推 journal 副本
该路径原有行为即不推 journal（非本次引入），但 meta 段加入后 `sync.noteMeta`
条目同样延后一轮入副本。已在 skip-PUT 分支补 `await _uploadJournal()`；
syncToRemote 有水位控制，无新条目时 no-op，重复调用无害。

### L-2 损坏重建路径未走 meta 段
`_recoverFromCorruptRemoteManifest` 补 `await _syncNoteMeta()`（置于
`_uploadJournal()` 前）：重建可能发生在 dataKey 迁移窗口，items.meta 或为
旧 key 残留，原实现要等下一轮才自愈；恢复轮自身也可能有 meta 脏行。
新增引擎测试「manifest 损坏重建轮同样执行 meta 段」锁定。

### Nits
- LocalFS `putMetaObject` 的 tmp 文件加微秒时间戳（与 putBlob 一致，防碰撞）。
- `note_meta_sync._payloadToJson` 防御性 try/catch（extra 透传内容来自历史
  payload，失败降级丢弃该条 payload 而非序列化崩溃）。
- WebDAV / SafeServer `putMetaObject` 失败由 StateError 统一改为
  `BackendUnavailableException`，便于引擎按类型分级日志/重试策略。

### 测试适配
`_MetaTestBackend.backupCorruptManifest` 改为真实模拟 LocalFS rename 语义
（清空 manifestCiphertext），否则本地重建的空 etag PUT 被 fake 的

## 2026-08-26 12:56 note_meta 同步上线（items.meta + per-note LWW）

**设计**：`docs/note-meta-sync-plan.md`（Q1-Q4 均按方案 a 落地）。

### 新增
- `packages/core/lib/src/sync/note_meta_sync.dart`：`NoteMetaSyncCodec`
  （wire JSON 编解码 + `AES-GCM(dataKey, kNoteMetaAad='note-meta-v1')` 信封封装 +
  per-note LWW 判定）。wire 格式 `{v:1, notes:{uuid:{pinned,archived,color,
  deleted,updated_at,payload}}}`；payload 为文件内明文对象（整文件已加密）；
  **不含 locked**（既有拍板决策：本地行为标志不同步）；extra 键透传前向兼容。
- 测试：`packages/core/test/sync/note_meta_sync_test.dart`（20 项：往返/容错分级/
  未来版本保护/AAD 域分离/LWW 四象限）、
  `packages/core/test/sync/note_meta_engine_test.dart`（7 项：双设备互不丢失/
  标签传播/墓碑传播+GC/解密失败自愈/不支持后端跳过/无脏行不建空文件/
  未来版本跳过）。
- `SyncBackend` 新增能力探测 `supportsMetaObjects`（默认 false，三后端覆写 true）
  + `putMetaObject`/`getMetaObject` + `kRemoteMetaMaxBytes=16MB`。

### 修改
- 三后端实现 items.meta 落点：LocalFS `keyring/items.meta`（tmp+rename 原子写）、
  WebDAV `<vault>/items.meta`、SafeServer `resources/items.meta`。**服务端零改动。**
- `database_handler.dart` 同步配套四方法：
  - `readAllNoteMetaIncludingTombstones()`（含墓碑全量读）
  - `mergeRemoteNoteMetas()`（单事务 per-note LWW 合并；远端胜出写 synced=1；
    墓碑应用擦 payload + 清 `_metaCache`）
  - `markNoteMetasSynced()`（条件置位 `WHERE updated_at=快照值 AND synced=0`，
    防上传期间再改动丢脏标记）
  - `purgeReportedNoteMetaTombstones()`（只删 deleted=1 AND synced=1）
- `sync_engine.dart`：`_syncNoteMeta()` meta 同步段——挂在 `_syncOnce` 成功路径
  （PUT 路径位于 `_uploadJournal()` **之前**，保证 meta journal 条目随本轮远端副本
  上传、无缺口；skip-PUT 路径同样执行），契约对齐 `_uploadJournal` 永不抛异常；
  解密失败走 Q1a 自愈（journal 留痕 + 忽略远端 + 本地全量覆盖上传）；
  wire 版本高于本端时整体跳过防降级覆盖；
  `_uploadNoteMetaSnapshot()` 接入两个 dataKey 迁移尾部（Q2a 重封重传）；
  journal 新事件类型 `sync.noteMeta`。
- 测试支撑：`FakeNoteMetaStore` mixin（sync_test_support.dart），8 个测试
  FakeBackend 补齐成员。

### 实施中发现的偏差修正
1. **journal 缺口回归**：初版把 meta 段挂在 `sync()` 外层成功出口，
   其 journal 留痕晚于 `_uploadJournal()`，导致 chaos 测试「远端副本完整覆盖
   本地 journal」失败（stash 对照确认为本改动引入）。已修复为 PUT 路径内置于
   journal 上传之前。
2. **supportsMetaObjects 能力探测**：方案未预见——默认空实现的 getMetaObject
   返回 null 与「远端无文件」不可区分，不支持的后端会把脏行误标 synced=1。
   新增布尔标志解决。
3. E 组 UI 刷新经核实**零改动**：home.dart `_onSyncStateChanged` 在同步完成态
   已调 `refreshNotes()` → `_sortAndStoreNotes()` 重读 metaMap 并重排序。
