## AppBar/状态栏配色与危险色修复（primary/error 暗色提亮系列）

> 更新时间 18:29–20:15，多次迭代后最终方案如下。完整踩坑过程见 `docs/THEME_PITFALLS.md`。

**根因（两处）**：M3 暗色面板会把 primary 和 error 提亮成浅色——黑色 seed 的 primary 变纯白
`#ffffff`、彩色 seed 的 primary 变浅蓝（blue `#a0cafd`）、error 变浅粉 `#ffb4ab`；亮色下
才是用户认知里的深色（黑 `#000000`、蓝 `#36618e`、error 深红 `#ba1a1a`）。

**修复**：
- `lib/models/app_theme.dart` `AppThemes.build`：
  - 新增亮色板 `appBarScheme = buildSeedColorScheme(seed, Brightness.light)`。
  - AppBar：亮色模式用 `appBarScheme.primary / onPrimary`（品牌深色，同按钮色）；
    暗色模式用 `scheme.surface / onSurface`（M3 默认 AppBar 背景，带轻微品牌色相，观感低调）。
    暗色 `backgroundColor` 必须显式赋值：滚动时 Flutter 的 `_resolveColor`（app_bar.dart:935）
    会用它兜底，传 null 会落到 `surfaceContainer` 导致滚动变色。
  - `systemOverlayStyle`：亮色 `statusBarColor=appBarScheme.primary` + 亮色图标；暗色传 null
    交给 AppBar 自动按背景计算。
  - Material 侧 error 恒定用亮色板：`scheme.copyWith(error/onError)` 作为 ThemeData.colorScheme
    （alertDialog 的 FilledButton 取 `Theme.colorScheme.error`，只改 Shad 不生效）。
- `lib/models/shad_theme.dart` `ShadThemes.build`：新增亮色板 `errorScheme`，
  `destructive / destructiveForeground` 恒定映射亮色板 error（深红 + 白字），暗色不再提亮成粉。

验证：`flutter analyze` 无错误；`flutter test` 40 个全部通过。

## 主题换色：灰度色被渲染成彩色的修复（最终：方案 A+C，最简单）

> 更新 18:04：方案 B（seed 亮度明暗 + ShadNeutralColorScheme）实测观感未提升、且自定义
> ShadCN 代码较多，已回退。最终采用最简单方案 A+C：两端共用 buildSeedColorScheme，中性
> seed 走 monochrome（明暗跟随全局暗色开关）。

根因：`ColorScheme.fromSeed` 默认 `tonalSpot` 只取 seed 的 HCT 色相、把 primary 色度
硬编码为 36，中性灰度色会被赋一个无意义伪色相并放大成彩色（米白/瓷白/墨黑偏青、纯黑偏粉紫）。
详见 `docs/THEME_COLOR_INVESTIGATION.md`。

- 新增 `lib/models/seed_scheme.dart`
  - `isNeutralSeed(Color)`：RGB 三通道最大差值 ≤ 26 判定为中性灰度色（全色库扫描恰好命中
    通用组 6 个灰度尾色 + 深邃组黑曜石，不误伤米色/奶油棕/灰豆绿等浅彩色）。
  - `buildSeedColorScheme(Color, Brightness)`：中性灰度 seed 用
    `DynamicSchemeVariant.monochrome`（色度恒 0）+ 传入 brightness；彩色 seed 保持
    默认 `DynamicSchemeVariant.tonalSpot`。
  - 顶部注释保留方案 B 备选思路（seed 亮度明暗 / ShadNeutralColorScheme），备忘用。
- `lib/models/app_theme.dart`：`AppThemes.build` 改用 `buildSeedColorScheme` 生成
  M3 ColorScheme（原 `ColorScheme.fromSeed(seedColor: seed, brightness)`）。中性=monochrome。
- `lib/models/shad_theme.dart`：`ShadThemes.build` 同样调用 `buildSeedColorScheme`
  （ShadCN 品牌色来源，保证 Material 与 ShadCN 两端同逻辑、同步换肤），再映射到
  `ShadSlateColorScheme`（无自定义中性色板）。
- 新增 `test/theme_neutral_verify_test.dart`：中性识别 / monochrome 输出为灰度 /
  彩色不误判为中性，全部通过。

验证：`flutter analyze` 三个 model 文件 + 测试无错误/警告；`flutter test test/theme_neutral_verify_test.dart`
全部通过。6 个灰度尾色修复后均为真正中性主题（不再彩色），明暗同彩色 seed 一样由全局暗色开关控制；
彩色与浅彩色（米色/灰豆绿等）行为不变。

备份：方案 B 版本 `temp/backups/seed_scheme.dart.20260817_180419.bak`、
`temp/backups/shad_theme.dart.20260817_180419.bak`；更早版本
`temp/backups/app_theme.dart.20260817_171334.bak`、
`temp/backups/shad_theme.dart.20260817_171334.bak`、
`temp/backups/shad_theme.dart.20260817_174407.bak`。

注：方案 A+C 下所有中性 seed 在暗色模式渲染为同一套深中性主题、亮色模式为同一套浅中性主题
