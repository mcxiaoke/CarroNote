## [2026-08-03 11:44:58] - 修复并行混沌测试：v4 改密码后他端同步被永久冻结
- **问题**：`chaos_multi_client_test.dart` 的「并行混沌（真实 118 克隆 + 改密码随机交织）」组 3 个 seed（12/345/6789）全部失败，均报「不变量1 失败：client 缺失从未被删除的笔记」。定位为 harness bug，非引擎缺陷。
- **根因**：v4（epoch 消除）后引擎不再设置 `SyncResult.passwordEpochMismatch`（恒 false），scenario-b「他端改了密码」改用 `requiresRelogin` 表达（sync_engine.dart:466-471 / 516-521）。但 chaos harness 的 `_reconcile` 仍以 `current.passwordEpochMismatch` 为循环条件 → 该协调逻辑成为死代码。结果：任一端改密后，其余客户端所有后续 sync 均以 scenario-b 中止（零 action、永不下载基线），且 `_reconcile` 不再触发重解锁 → 未下载基线的一端永久缺失笔记 → 不变量1 失败。
- **修复**：`_reconcile` 循环条件改为 `current.passwordEpochMismatch || current.requiresRelogin`，并在注释中说明 v4 信号迁移；两种信号下均按原逻辑用 `knownPasswords`（倒序，最新优先）重解锁远端 keyring、刷新 `c.keyring`/`c.engine.keyring`/`c.currentPassword` 后重试同步。`_dataKey` 为 getter（`=> keyring.dataKey`），改 keyring 引用即生效。
- **验证**：`dart analyze` 0 issue；并行混沌 3 seed 全通过（119s）；全文件 13 项（并行混沌 + P2 定向故障注入 12 项）全部通过。诊断脚本（temp/chaos_diag.dart）确认首轮同步 47/47 下载正常，问题仅在改密后的协调路径。
