## [2026-07-30 09:39:15] - 修复混沌测试两处问题（测试脚本 bug + 测试 model 盲区）

- **修复测试脚本递归 bug**: 
  - `test/sync/chaos_multi_client_test.dart` 的 `ChaosHarness._sync` 方法内部错误地递归调用自身（`await _sync(c, tag: "wrap")`），导致栈溢出（5642 层栈帧后崩溃），测试根本无法运行。
  - 改为调用 `c.engine.sync()`，由外层 `_sync` 做动作记账和 trace 输出。

- **修复测试 model 对冲突副本的盲区**:
  - 引擎 `SyncEngine._preserveConflictCopy` 在 LWW 冲突时会把败方内容另存为新 UUID 笔记（内容=败方内容 → hash=败方 hash），这是合法行为。
  - 原 fail-fast 检查逻辑有错误假设："一个 hash 只能属于一个 uuid，若本地某行 hash 属于其他 uuid 即判为跨 uuid 错位"。
  - 这导致冲突副本的合法 hash 共享被误判为错位（seed=1 step 20 即此误报）。
  - 修复方式：
    1. 引擎侧（`lib/sync/sync_engine.dart`）：给 `_uploadNote` 加可选 `message` 参数；`_preserveConflictCopy` 两个分支调用时传 `message: 'conflict-copy from <srcUuid>'`，让冲突副本的 upload action 可被上层识别。
    2. 测试侧（`test/sync/chaos_multi_client_test.dart`）：`_sync` 仅对带 `conflict-copy from ` 标记的 action 把 `(uuid, hash)` 纳入 `LogicalModel`；其他普通 upload/download/delete 保持严格检查。
  - 这样既不误判合法的冲突副本 hash 共享，也不掩盖引擎真实的跨 uuid 错位 bug（错位的 hash 不会被标记为 conflict-copy，仍会被 fail-fast 抓到）。
