## [2026-08-02 16:00:19] - 重构：解密缓存轻量收敛（DAO 内收口 + 实例字段）
- **背景**：此前缓存维护散落在每个写路径（`storeNote`/`updateNote`/`softDelete`/`restoreNote`/`hardDelete`/`hardDeleteByUuid` 各自调 `_upsertCacheEntry`/`_patchCacheEntryById`/`_removeCacheEntryById`/`_removeCacheEntryByUuid`，`markSynced*` 三处内联重建），易漏改字段（已踩过 updatedAt 导致远端墓碑未生效的坑）。
- **收口为 4 个私有方法**：`_invalidateCache` / `_upsertCacheEntry`（按 uuid 整条覆盖）/ `_removeCacheEntry({id,uuid})` / `_applySyncedToCache({uuids,exclude})`（合并 markSynced 全系列）。删除 `_markCachedSynced` / `_patchCacheEntryById` / `_removeCacheEntryById` / `_removeCacheEntryByUuid` 及 markSynced* 内联重建。每个写路径只调其中之一。
- **结构杜绝漏改字段**：`softDelete`/`restoreNote` 改为「取缓存旧条目 → 叠加增量重建完整对象 → 整条 `_upsertCacheEntry` 覆盖」，updatedAt 随对象带入，写路径无法遗漏 → 从根上消除同步 LWW 时间戳误判。
- **`_notesCache` 由 `static` 改为实例字段**：去掉多 DB 实例（测试反复 setDatabaseForTesting 建新库）共享同一份缓存的隐性耦合；`setDatabaseForTesting` 改为 `instance._notesCache = null` 清空。`NotesDatabase` 仍是缓存持有者，UI / SyncEngine 调用点不变（最小改动面）。
- **验证**：`flutter test` 全量 250 项通过；`flutter analyze` 无告警。

## [2026-08-02 15:43:40] - 修复：缓存手术式更新遗漏 updatedAt，导致远端墓碑未生效（同步回归）
- **根因**：P1 的"手术式缓存更新"把 `softDelete` / `restoreNote` 改为调用 `_patchCacheEntryById`，但该方法只改 `deleted`/`synced`，**未同步 DB 里写入的新 `updatedAt`**。缓存条目保留旧时间戳，使同步引擎 `_buildLocalManifest` 读到过期 `updatedAt`，远端墓碑的 LWW 时间判定被打平（本地时间 == 远端时间），平局回退选本地 → 远端墓碑被忽略。
- **修复**：`_patchCacheEntryById` 新增 `updatedAt` 形参，并在 `softDelete` / `restoreNote` 调用处传入真实的 `now`，保证缓存与 DB 时间戳一致。等价于回归前 `_invalidateCache()`（每次都从 DB 重读）的行为，但保留零重解密收益。
- **清理**：移除诊断用的 `print('DBG ...')` 临时调试语句（`database_handler.dart` 的 `updateNoteByUuid`、`sync_engine.dart` 的 `_resolveConflict` / `_downloadNote`）。
- **验证**：`flutter test test/sync/sync_engine_test.dart` 24 项全过（含此前失败的"远端墓碑 → 本地也标记为软删除"）；`flutter test` 全量 250 项通过；`flutter analyze` 无告警。

## [2026-08-02 15:16:10] - P1 性能优化：解密结果缓存，消除主线程反复全量解密卡顿
- **根因**：`readAllNotes` 每次都同步解密全部 41 条笔记（AES-GCM，~2s/次），且 autoSync 每 ~3s 触发 `readAllNotesIncludingDeleted` ×2~3 + 同步完成后再 `refreshNotes` 一次，导致主界面周期性 2 秒冻结（日志实证）。P0 只修了渲染，未触碰解密。
- **新增解密缓存** `NotesDatabase._notesCache`（含墓碑的全量明文），`readAllNotes` / `readAllNotesIncludingDeleted` 命中缓存直接返回，跳过解密。
- **失效策略**：仅「内容写」失效（`storeNote` / `updateNote` / `updateNoteByUuid` / `softDelete` / `hardDelete` / `hardDeleteByUuid` / `restoreNote` / `reEncryptAllNotes*`）；`markSynced*` 系列**不**失效，而是直接刷新缓存条目的 `synced`/`syncedHash`/`syncedDeleted` 标记（正文不变，无需重解密），保证同步后的 `refreshNotes` 在内容无变化时零解密。
- **生命周期**：`clearDataKey` / `close` / `deleteDbFile` / `setDatabaseForTesting` / 重新打开数据库连接时统一清空缓存，避免跨会话或跨测试命中旧明文。
- **正确性验证**：同步引擎只用 `contentHash`/`deleted`/`updatedAt` 决定上传与收敛，不依赖缓存里的 `synced` 标记；`markSynced*` 已同步刷新缓存标记，现有断言 `note.synced==true` 的测试不受影响。
