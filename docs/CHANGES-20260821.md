# CHANGES-20260821

## H-05 日志服务器 Token 认证

> 时间：2026-08-21 12:4x (GMT+8)
> 来源：`docs/code-review-20260821.md` H-05
> 验证：`flutter analyze` 0 issues；`flutter test` 86 项全过

### 改动
- `lib/src/logger/log_webserver.dart`：每次 `start()` 生成随机 6 位数字 token（`Random.secure()`），所有请求必须通过 `_checkToken()` 校验（URL `?token=xxx` 或 HTTP header `token`），不匹配返回 403
- `assets/web/dashboard.html`：`api()` / `dlSet()` / `connectLogs()` 均通过 `withToken()` 追加 token 参数
- `lib/src/logger/log_webserver.dart` `_buildHtmlPage()`：JS 从 URL 提取 token，WebSocket 和下载链接均携带 token
- `lib/src/logger/log_webserver.dart` `_serveDashboard()`：服务 dashboard HTML 时注入 `window.__TOKEN__`
- `lib/views/settings/sync_diagnostics_page.dart`：状态文本展示带 token 的完整 URL；安全提示更新
- `assets/translations/zh-CN.json` + `en-US.json`：更新状态文本和安全提示翻译

### 影响
此前日志服务器绑定 `0.0.0.0` 且无任何认证，局域网任意设备可直接访问 `/api/download/db` 下载加密数据库。现在每次启动生成随机 token，用户需从诊断面板获取带 token 的完整 URL 才能访问。

### H-06 wrapDecryptionError 异常类型匹配修复（`packages/core/lib/src/crypto/crypto.dart` + `packages/core/lib/src/sync/sync_error.dart`）
- import 添加 `SecretBoxAuthenticationError`；`_aesGcmDecrypt` catch 处改为 `isTagError: e is SecretBoxAuthenticationError`
- `wrapDecryptionError` 签名改为 `required bool isTagError`，删除 `InvalidTag` 字符串匹配死代码
- **影响**：项目使用 `package:cryptography`，GCM 认证失败抛 `SecretBoxAuthenticationError`，旧代码检查 `InvalidTag`（pointycastle 的异常）在所有构建模式下均不匹配，导致所有解密失败都被归为"非 tag 错误"，无法区分密钥不匹配与数据损坏。

### M-01 _decryptField 异常类型修正（`packages/core/lib/src/db/database_handler.dart:469`）
- 解密失败不再包装为 `DataKeyNotSetException`，改为 `on SyncDecryptionException { rethrow; }` + 其他异常包装为 `SyncDecryptionException`
- **影响**：`DataKeyNotSetException` 语义为"dataKey 未设置"，但解密失败的实际原因是密钥不匹配或数据损坏，异常类型误导向。改用 `SyncDecryptionException` 与 `SyncCrypto.open` 的异常体系一致。

### M-02 storeNotesInTransaction 缓存 id 回填修复（`packages/core/lib/src/db/database_handler.dart:805`）
- 事务批量插入后缓存更新从 `_upsertCacheEntry(entry.note)` 改为 `_invalidateCache()`
- **影响**：事务内 insert 返回的自增 id 未回填到 `entry.note`，缓存条目 id 为 null，后续 `readNote(id)` / `softDelete(id)` 会因 id==null 失败。直接失效缓存，下次读取时从 DB 重建（含正确 id）。

### M-04 空 catch 补日志（`packages/core/lib/src/db/database_handler.dart`）
- `getPendingReuploadUuids` 和 `getGcOrphanCandidates` 的空 `on Exception` / `on Object` catch 加 `Log.db.w` 日志
- **影响**：JSON 解析失败被静默吞掉，调试时无法发现损坏数据。

### M-05 sync_config 空 catch 补日志（`lib/sync/sync_config.dart`）
- `_preloadCredentials` 两个空 catch 加 `Log.sync.w` 日志
- **影响**：凭据预加载失败被静默吞掉，同步异常时无法追溯。

### M-06 getFileAsString 异常分层捕获（`lib/models/file_handler.dart:182`）
- `catch (e)` 拆为 `on FileSystemException` + `on Object catch (e, st)` 两层，均记日志
- **影响**：文件读取异常被笼统捕获，无法区分文件不存在与权限/IO 错误。

### M-07 应用更新版本号写入时机修正（`lib/main.dart`）

- **影响**：先备份再更新版本号，若备份失败版本号已变，下次启动会跳过备份。

### M-09 journal 临时文件并发碰撞修复（`packages/core/lib/src/sync/journal.dart`）

- **影响**：多客户端并发写日志时 `.tmp` 文件名碰撞，后写者覆盖前写者的临时文件。

### M-11 路由参数类型注释修正（`lib/routes/route_generator.dart`）

### M-14 导航项 onTap 可空化（`lib/widgets/shad_nav_items.dart` + `lib/widgets/nav_list.dart` + `lib/widgets/drawer.dart`）

## 代码审查最紧急修复（H-01 ~ H-04 + M-10）

> 时间：2026-08-21 11:5x (GMT+8)
> 来源：`docs/code-review-20260821.md` 第五节"最紧急的修复"
> 验证：`flutter analyze` 零问题；`dart test` crypto 32 项全过；`flutter test` 86 项全过

### H-01 Argon2id 密码编码修复（`packages/core/lib/src/crypto/crypto.dart:212`）
- `SecretKey(password.codeUnits)` → `SecretKey(utf8.encode(password))`
- **影响**：`String.codeUnits` 返回 UTF-16 编码单元，经 `Uint8List.fromList()` 截断为低 8 位，
  非 ASCII 密码（如中文）熵严重损失且可能碰撞。改用 UTF-8 编码后与 PBKDF2 路径统一，
  符合 RFC 9106 规范。

### H-02 原子迁移补入 note_meta.payload 重加密（`packages/core/lib/src/db/database_handler.dart`）
- `reEncryptAllNotesAtomically` 方法在事务内补入 `_readMetaPayloadsPlain` + `_encryptField(newKey)` + `txn.update(note_meta)` 三步
- **影响**：此前原子迁移只重加密了 notes 表的 title/description，遗漏 note_meta.payload。
  迁移后 dataKey 更新为 newKey，但 payload 仍为 oldKey 加密的密文，解密失败降级为空，
  **用户所有标签永久丢失**。现已与非原子版本 `reEncryptAllNotes` 逻辑完全一致。

### H-03 destroyImportCredentials 字符串 "null" 修复（`lib/models/file_handler.dart:182` + `lib/data/preference_and_config.dart:663`）
- `setImportPassPhrase` 签名由 `String` 改为 `String?`，调用处 `"null"` → `null`
- **影响**：字符串 `"null"` 会被 `isNotEmpty` 判断误认为存在导入密码，与 `importPassPhraseHash = null` 的语义矛盾。

### H-04 iOS 备份异常捕获（`lib/utils/scheduled_task.dart:211-234`）
- `iosBackup()` 包裹 try-catch，异常时记录 `lastBackupError` 并返回 `false`；空目录时返回 `false`
- **影响**：此前 `iosBackup` 无 try-catch，写入异常穿透 `backup()` → `Session.logout()` 导致用户无法登出。
  与 `androidBackup`/`desktopBackup` 的异常处理风格统一。

### M-10 生物识别 localizedReason 国际化（`lib/views/authentication/login.dart:845`）
- `'Login using your biometric credential'` → `'Login using your biometric credential'.tr()`
- **影响**：系统生物识别弹窗文案未走 i18n，与 `biometric_setting.dart:80` 同一参数的处理方式不一致。
