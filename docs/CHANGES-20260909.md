## 2026-09-09 修复 Release workflow 产物路径不匹配导致发布失败

> 关联 run：https://github.com/mcxiaoke/CarroNote/actions/runs/34306999919
> 现象：Build Windows / Build Android 均成功，仅 `Create GitHub Release` 失败：
> `no matches found for artifacts/android-build/CarroNote-2.9.2-arm64-v8a.apk`（exit 1）。未 commit。

* **根因（已实证）**：`upload-artifact@v4` 的上传根目录 = 路径中首个通配符之前的目录。原配置
  `path: build/app/outputs/**/CarroNote-*.apk` 的根目录是 `build/app/outputs`，因此产物 zip 内保存为
  `flutter-apk/CarroNote-2.9.2-*.apk`；下载后落到 `artifacts/android-build/flutter-apk/`，而 release 步骤按
  `artifacts/android-build/CarroNote-*.apk` 扁平路径取文件，必然找不到。
  已下载实际产物 zip 核对，内部条目确为 `flutter-apk/CarroNote-2.9.2-{arm64-v8a,armeabi-v7a,x86_64,fat}.apk`。

* **修改（`.github/workflows/release.yml`）**：
  1. 两个构建 job 先把产物复制到工作区根下的 `dist/`，再上传 `dist/CarroNote-*.apk` / `dist/CarroNote-*.zip`
     —— 根目录变为 `dist`，产物结构扁平，不再依赖 Flutter 输出目录层级；
  2. 上传加 `if-no-files-found: error`，改名或目录变动时立即失败，不再静默产出空产物；
  3. Windows 打 zip 前先 `New-Item -Force dist`，避免 `Compress-Archive` 目标目录不存在而报错；
  4. Android 的 fat APK 改为 `find build/app/outputs -name app-release.apk` 独立定位，不再假定与 split APK 同目录；
  5. release job 新增 `Collect release assets` 步骤：用 `find artifacts -type f -name <精确文件名>` 逐个定位并复制到
     `release-assets/`，缺失时打印 `::error::` 并列出实际文件清单后退出 1（排障信息完整）；
  6. `gh release create` 改为引用 `release-assets/*`；并加幂等分支——release 已存在时改为
     `gh release upload --clobber`，避免重跑作业时因 tag 已存在而失败。

* **验证**：用真实产物布局在本地 temp 目录跑通 `Collect release assets` 脚本（嵌套 `flutter-apk/` 路径下 5 个文件全部
  正确收集）；YAML 解析通过，3 个 job、步骤序列正确。未做 commit / push / 打 tag。
