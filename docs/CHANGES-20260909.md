## 2026-09-09 修复 Windows 关窗鼠标沙漏（根因：destroy() 强毁窗口导致引擎挂起）

* **现象与根因**：点 X 后窗口立即隐藏，但鼠标沙漏 1-3 秒。根因是 `windowManager.destroy()` 在原生侧强制销毁窗口，Flutter Windows 引擎在关闭流程中被挂起；改为 `setPreventClose(false)` + `close()` 走系统正常关闭路径后，实测沙漏消失。
* **修改文件**：
  1. `lib/utils/desktop_window_native.dart`（`onWindowClose` finally）：`windowManager.destroy()` 改为 `setPreventClose(false)` + `close()`（实测解决沙漏，用户验证）。
  2. `lib/sync/sync_service.dart`（`dispose`）：在途同步等待由默认 10s 改为 500ms 超时，超时且仍在同步时补 warn 日志（加固保留，非本次根因）。
  3. `lib/src/logger/log_webserver_io.dart`（`stop`）：WebSocket `close()` 加 200ms 超时（加固保留，非本次根因）。
* **验证**：用户实测关窗无沙漏；`dart format` ✅ | `flutter analyze` 0 issues ✅ | `dart test packages/core/test` 443 passed ✅ | `flutter build windows --debug` ✅

## 2026-09-09 Windows Portable Mode 支持（portable.ini 自动检测）

* **目标**：支持 U 盘便携模式——把 exe 放 U 盘同级放一个 `portable.ini`，所有数据自动写入 exe 旁边的 `app_data/` 子目录，实现随盘携带、零配置。
* **已有基础**：项目已有 `SN_DATA_DIR` 环境变量覆盖机制（DB / prefs / 日志重定向），本次在此基础上加自动检测，无需用户设环境变量。
* **修改文件**：
  1. `lib/src/platform/data_dir_override_native.dart`：
     - 新增 `_detectPortableMode()`：检测 exe 同级目录是否存在 `portable.ini`，存在则返回 `<exe目录>/app_data` 作为数据目录。
     - `kPortableDataDir` 常量值为 `app_data` 而非 `data`——Flutter Windows 构建产物 exe 同级已有 `data/` 目录（含 `app.so`、`flutter_assets/`、`icudtl.dat` 等运行时文件），同名会冲突。
     - `applyDataDirOverride()` 增加便携模式检测（优先级低于 `SN_DATA_DIR` 环境变量）。
     - 新增 `getEffectiveAppSupportPath()`：统一获取有效应用数据目录路径（override 优先，否则回退 `getApplicationSupportDirectory()`），供调用方替代直接调 path_provider。
     - `data_dir_override_web.dart` 补 `getEffectiveAppSupportPath()` 的 web stub。
  2. `lib/sync/sync_service.dart`：`_openJournal` 中 `getApplicationSupportDirectory()` 改为 `getEffectiveAppSupportPath()`，让同步 journal 目录也跟随 portable mode。
  3. `lib/utils/vault_backup.dart`：`backupVaultBeforeReset` 中同理改用 `getEffectiveAppSupportPath()`，让重置前备份也写入 portable 数据目录。
* **验证**：`dart format` ✅ | `flutter analyze` 0 issues ✅ | `dart test packages/core/test` 443 passed ✅

## 2026-09-09 修复 Release workflow 产物路径不匹配导致发布失败

> 关联 run：https://github.com/mcxiaoke/CarroNote/actions/runs/34306999919
> 现象：Build Windows / Build Android 均成功，仅 `Create GitHub Release` 失败：
> `no matches found for artifacts/android-build/CarroNote-2.9.2-arm64-v8a.apk`（exit 1）。未 commit。

* **根因（已实证）**：`upload-artifact@v4` 的上传根目录 = 路径中首个通配符之前的目录。原配置
  `path: build/app/outputs/**/CarroNote-*.apk` 的根目录是 `build/app/outputs`，因此产物 zip 内保存为
  `flutter-apk/CarroNote-2.9.2-*.apk`；下载后落到 `artifacts/android-build/flutter-apk/`，而 release 步骤按
  `artifacts/android-build/CarroNote-*.apk` 扁平路径取文件，必然找不到。
  已下载实际产物 zip 核对，内部条目确为 `flutter-apk/CarroNote-2.9.2-{arm64-v8a,armeabi-v7a,x86_64,fat}.apk`。

* **修改（`.github/workflows/release.yml`）**：
  1. 两个构建 job 先把产物复制到工作区根下的 `dist/`，再上传 `dist/CarroNote-*.apk` / `dist/CarroNote-*.zip`
     —— 根目录变为 `dist`，产物结构扁平，不再依赖 Flutter 输出目录层级；
  2. 上传加 `if-no-files-found: error`，改名或目录变动时立即失败，不再静默产出空产物；
  3. Windows 打 zip 前先 `New-Item -Force dist`，避免 `Compress-Archive` 目标目录不存在而报错；
  4. Android 的 fat APK 改为 `find build/app/outputs -name app-release.apk` 独立定位，不再假定与 split APK 同目录；
  5. release job 新增 `Collect release assets` 步骤：用 `find artifacts -type f -name <精确文件名>` 逐个定位并复制到
     `release-assets/`，缺失时打印 `::error::` 并列出实际文件清单后退出 1（排障信息完整）；
  6. `gh release create` 改为引用 `release-assets/*`；并加幂等分支——release 已存在时改为
     `gh release upload --clobber`，避免重跑作业时因 tag 已存在而失败。

* **验证**：用真实产物布局在本地 temp 目录跑通 `Collect release assets` 脚本（嵌套 `flutter-apk/` 路径下 5 个文件全部
  正确收集）；YAML 解析通过，3 个 job、步骤序列正确。未做 commit / push / 打 tag。
