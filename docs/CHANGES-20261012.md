# 2026-10-12 变更记录

## 2026-10-12 15:43:04 — feat(security): PIN Lock 安全加固（移除明文 wrapKey、方案 B 改密销毁凭据、桌面端 128MB Argon2id 与硬件设备绑定）

### 需求与背景

针对 PIN Lock 架构进行全面安全评估后发现：
1. **明文包裹密钥风险**：原架构为支持改密无感静默刷新，在安全存储中保留了未加密的 `_securePinWrapKey`。在桌面端（无 App 沙盒，依赖 Windows DPAPI）同用户下的恶意程序或木马可读取该 key 并瞬间绕过 PIN 解开主密码。
2. **纯软件客户端限制**：在线 5 次错误熔断易被脱机绕过，6 位纯数字 PIN 的数学熵较低（约 20 bits）。
3. **改密安全妥协**：改主密码时后台保留旧包裹密钥刷新凭据违反了最少权限和零信任原则。

### 核心改动

1. **彻底消除 `_securePinWrapKey` 明文存储，简化为单层直接信封**：
   - `lib/models/pin_auth.dart`：抛弃两层信封结构，改为由 `KDF(PIN + devicePepper)` 直接派生密钥封印 vault 主密码（AES-256-GCM，AAD=`pin-auth`，`v1:` 前缀）。
   - 安全存储中仅保留 `_securePinKdfKey` 与 `_securePinAuthKey`，彻底删除并清理历史 `_securePinWrapKey` 与 `_securePinEnvelopeKey`。
   - `verifyPin` 中提供旧版双层信封向后兼容路径，老凭据首次验证通过后自动静默升级为加固单层信封并删除残留 key。

2. **采纳方案 B：修改主密码时自动销毁 PIN 凭据并关闭 PIN 锁**：
   - `lib/models/session.dart`：`Session.onPasswordSet` 重构为 async，修改密码时若开启了 PIN 锁，自动调用 `await PinAuth.disable()` 彻底清除所有 PIN 凭据并关闭开关，杜绝任何钥匙落盘。
   - `lib/models/session.dart`：从 `Session.login` 中彻底移除无用的 `PinAuth.refreshCredential()` 调用。
   - `lib/views/change_passphrase.dart`：修改密码成功后，若原本启用了 PIN 锁，通过 SnackBar 明确提示用户“密码已修改。出于安全考虑，PIN 锁已自动关闭，如需使用请重新设置。”
   - `assets/translations/zh-CN.json` / `en-US.json`：补充中英文多语言资源。

3. **桌面端平台自适应 Argon2id KDF 参数加固（128 MiB, t=4, p=4）**：
   - 本地实测耗时基准（Windows）：原版 32MB/t3/p2 为 173ms；加固版 128MB/t4/p4 为 658ms（完全在 1 秒以内，体感流畅）。
   - 桌面端（Windows / Linux / macOS）自动启用 `memoryKiB: 131072 (128 MiB)`, `iterations: 4`, `parallelism: 4`；
   - 移动端（iOS / Android / Web）自动保持 `memoryKiB: 32768 (32 MiB)`, `iterations: 3`, `parallelism: 2`；
   - 专用芯片 AT 成本（Area-Time Complexity）提升 21.3 倍以上，GPU 显存并发吞吐量压制 8~12 倍。

4. **物理设备硬件绑定（Device Binding / 防脱机拷贝破解）**：
   - 密钥派生时将 PIN 与当前设备的物理硬件唯一特征（Windows `deviceId` / Linux `machineId` / macOS `systemGUID` / 移动端硬件 ID）深度混合为 `pin#devicePepper`。
   - 即使攻击者将安全存储文件与数据库拷走到异地算力集群，缺少原物理设备硬件指纹，穷举结果必然全部解封失败。
