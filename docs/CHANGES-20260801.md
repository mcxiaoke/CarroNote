### 修复清单

1. **DS002 P3** `_hasEffectiveChange` 排除 `updatedBy`：新增 `_semanticItemsEqual` 逐字段比较
   （hash/deleted/updatedAt/createdAt/deletedAt/contentSize/blobKeyEpoch），

6. **DS001 P6** `switchBackend` 不检查 `_syncInProgress`：
   开头加互斥守卫，同步进行中切换后端抛 `StateError`。
7. **DS002 P5** `_preserveConflictCopy` `on Exception` 兜不住 `RangeError`：

8. **DS002 P6** `markAllSynced()` 无条件全量：
   新增 `markAllSyncedExcept(Set<String> exclude)`，本轮 uploadFailed 的 uuid 排除在
   全量同步标记之外；新增 `removePendingReuploadUuids(Set<String> uploadedOk)`，
   pending 重传成功后只移除成功项。

## [2026-08-01 15:48:02] - 修复：空闲锁定 logout 后误回「输入两次密码」初始化界面

> 现象：Android 上空闲锁定后**有时**回到设置密码页（而非登录页）。
> 根因：`AuthWall` 用 `AppBootState.vaultInitialized`（启动时缓存一次的静态值）判定路由，
> 而该值仅两处赋值：`main()` 启动查询、`_performLocalDataReset` 置 false。
> 首次启动（false）→ 设置密码成功 → 进 home 后，**没有任何代码把它置 true**；
> 空闲锁定 `logout()` 导航回 `/authwall` 时仍读到 false → 误走 `SetEncryptionPhrasePage`。
> 重启过 app 的进程不受影响，故表现为「有时」。

### 修改文件

- **`lib/views/authentication/set_passphrase.dart`**：`_initKeyring` 成功后 `AppBootState.vaultInitialized = true`（新增 `authwall.dart` import）。
- **`lib/views/authentication/login.dart`**：`_onLoginSuccess` 登录成功后同样同步置 true（兜底，登录页应回登录页）。

### 验证

- `flutter analyze` 相关 4 文件：0 issue。

## [2026-08-01 09:08:27] - 冲突判定改为「共同祖先 base hash」，修复无限增殖与真并发静默丢数据

> 用户决策：**先修冲突判定 base hash（推荐）**，删除架构改造（独立 trash_notes 表 + 服务端真实删除）延后。
> 根因：原冲突判定用 `updatedAt` 时间差（>5 分钟判「真冲突」并保留副本）整个方向用反——衡量的是内容「新旧」而非「双方是否都偏离了上次同步的共同版本」，导致两向严重缺陷：
>   · **单边编辑误判为冲突** → 每台设备各把手里的旧版本另存成新 uuid 副本 → 长期测试实测**每代 +3 副本**无限增殖；
>   · **真并发误判为 LWW 覆盖** → 败方编辑被静默丢弃（实测 A 写的 v2 同步后凭空消失）。
> 正解：以本地 `syncedHash`（上次同步收敛时的 `content_hash`）为三方合并 base，区分「单边编辑」与「真并发冲突」。

### 新增 / 修改文件

- **`lib/models/safenote.dart`**：`SafeNote` 新增 `final String? syncedHash;` 字段；构造参数、`copyWith`、`fromJson`/`toJson`/`toString` 全部接入。该字段是 base-hash 判定的数据基础（本地收敛基线）。
- **`lib/data/database_handler.dart`**：
  - 生产 `_initDB` 升到 **DB version 3**，新增 `_upgradeDB`：v2→v3 `ALTER TABLE` 加 `synced_hash` 列，并对 `synced=1` 的历史笔记回填 `synced_hash = content_hash`（无基线的新笔记留 null，触发保守退化）。
  - 新增 `@visibleForTesting` 静态迁移钩子 `upgradeDBForTesting` / `_upgradeDBStatic`，供测试文件库对称挂载 `onUpgrade`，避免存量 v2 文件库 `no such column: synced_hash`。
- **`lib/sync/sync_engine.dart`**：
  - 冲突判定（约 1183–1200 行）改为 base-hash：`base = localNote?.syncedHash`；`localChanged = base==null || localItem.hash != base`，`remoteChanged` 同理；`shouldPreserveCopy = localChanged && remoteChanged && 双方活跃(非删) && hash 不同`。
  - **base==null 保守退化**：本地无同步基线（新笔记 / 迁移前未同步）时退化为「内容不同即保留副本」——绝不丢数据（顶多多留一份且仍要求双方活跃），也绝不复活删除。
  - 废弃常量 `kConflictPreserveThresholdMs` 已移除（仅保留注释说明旧逻辑为何错误）。

### 测试修复（让用例走真实 base 路径而非退化蒙混）

- **`test/sync/multi_device_test.dart`**：
  - 用例 544（单边编辑）：改用 `readNoteByUuid` + `copyWith` 保留 `syncedHash`（原用 `SafeNote(...)` 新建会抹掉 base 触发退化），断言单边编辑**不增殖**（Expected 1）。
  - 用例 471（双设备真分叉）：重写为「显式 `syncedHash=baseHash(v1)` 重建设备 B 视角」，断言 v3 胜、v2 以新 uuid 保留副本。
  - 用例 605（真并发，时间差 < 旧阈值）：发现 `NotesDatabase` 为纯单例，`dbA`/`dbB` 无法共存（旧交替写法实际两库指向同一内存库，仅因 base=null 退化蒙混过关），彻底改为忠实单库构造（与 471 同范式）：base=v1，远端推到 v2，本地离线改 v3 → sync，断言 v2、v3 都活。
  - 结果：**multi_device_test 13/13 通过**。
