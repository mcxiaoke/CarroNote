## [2026-08-10 12:11] B-H1 HTTP 重定向静默丢失修复：两个后端的 HTTP 客户端层重做

- **背景（审查报告 B-H1，已核实）**：package:http 便捷方法（`client.get/put/delete`）默认 `followRedirects=true`，底层 dart:io 自动跟随重定向，导致两类问题：
  1. 301/302/303 会把非 GET 方法重做成 GET 重发（写操作被降级）：WebDAV/SafeServer 对 PUT manifest、PUT/DELETE blob 等做 301（http→https、补尾斜杠，坚果云/Nextcloud 常见）→ PUT 变 GET → 返回 200 → `putManifest`/`putBlob` 误判成功 → **manifest 实际未写入、ETag 错乱，数据静默丢失**；
  2. 跟随重定向时原请求 headers（含 Authorization Basic/Bearer）会被带到重定向目标的任意 host，**凭据跨站泄露**。
- **`packages/core/lib/src/sync/backends/http_util.dart`（新增）**：统一发送助手 `sendWithRedirectPolicy`，所有请求 `followRedirects=false`，3xx 按显式规则判定是否手工重发：
  - 同源 = scheme+host+port 完全一致（默认端口归一）；
  - 读取类（GET/HEAD/PROPFIND/MKCOL）允许 301/302/303/307/308 同源跟随，并放宽 http→https（相同 host:port 仅换 scheme）安全升格跟随；
  - 写操作（PUT/DELETE/COPY/POST）仅 307/308 且严格同源时跟随（语义保留）；301/302/303 **原样返回 3xx**，由调用方既有非 2xx 分支响亮失败，绝不降级为 GET；
  - 跨源一律不跟随（杜绝凭据泄露）、3xx 无 Location 原样返回、上限 5 跳防环（超限抛 `http.ClientException`）。
- **两个后端全部 HTTP 调用改走该助手**（各新增私有 `_sendHttp` 封装）：
  - `webdav_backend.dart`：getManifest / putManifest / getBlob / putBlob / deleteBlob / deleteBlobSoft(COPY+DELETE) / listBlobs / listOrphanBlobs / purgeOrphans / journal 三件套 / manifest 环形备份 / listManifestBackups / readManifestBackup / backupCorruptManifest / ping / _mkcol 等约 20 处；
  - `safe_server_backend.dart`：health / getManifest / putManifest / getBlob / putBlob / deleteBlob / listBlobs / `_postResource` / `_getResource` / `_putResource` / `_deleteResource` / ping 等约 22 处（多数收敛到 4 个资源助手 + 上述端点）。
- **新增测试（全部通过）**：
  - `packages/core/test/sync/http_util_test.dart`（14 例）：覆盖 followRedirects=false、PUT/POST 301 不跟随、PUT/DELETE 307 同源跟随（验证保持 method/body/Authorization）、跨源 307 拒绝、GET 301 同源及 http→https 升格跟随、端口变化拒绝、PROPFIND/MKCOL 跟随、无 Location、重定向环超限；
  - `packages/core/test/sync/backend_redirect_test.dart`（6 例）：两个后端 putManifest/putBlob 遇 301 抛 `BackendUnavailableException`（拒绝假成功，仅 1 次请求）、307 同源跟随保持 PUT+密文+认证头并从新 ETag 取乐观锁。
- **验证**：`dart analyze packages/core` / `flutter analyze lib test` 0 issue；`dart test packages/core/test` 265 项全部通过（此前 242 + 新增 20，另有长期存续测试在跑）。

## [2026-08-10 10:30] blob 寻址口径消歧：`SyncCrypto.contentHash` → `sha256Hex` + 补不变量测试

- **背景（先澄清：不是线上缺陷）**：`docs/crypto-overview-20260810.md` §5.2 曾把「`SafeNote.computeHash` 与 `SyncCrypto.contentHash` 不等价」写成"混用会导致全部 blob 不可寻址"，读起来像已发生的 bug。核查后确认**当前实现没有混用**：blob 的 id、GCM AAD、manifest.hash 三处一致地只用 `SafeNote.computeHash(title, description)`（`sync_engine.dart:1955` seal / `1962` putBlob / `1367` manifest / `2039` open / `2091` getBlob / `2154` M7 校验），`SyncCrypto.contentHash` 在生产代码中**零调用点**（只被同文件 `hashString` 使用），服务端（Go/Node）也不校验 blob 字节哈希。
- **真实风险**：该名字与 `SafeNote.contentHash` 字段、DB 列 `content_hash` 三者重名而语义不同，容易被"顺手统一"成对 payload 字节求哈希；一旦改动，存量 blob 全部失联且**不产生任何编译错误**。本次处理的是这个隐患，而非缺陷。
- **`packages/core/lib/src/crypto/crypto.dart`**：公开别名 `contentHash(bytes)` 与私有 `_sha256Hex(bytes)` 本就是同一实现，合并为单一公开入口 `sha256Hex(bytes)`；`computeKeyFingerprint` / `computeDataKeyFingerprint` / `hashString` 三处调用同步更名。补文档注释：明确该函数是通用原语、不承载协议语义，blob 身份只由 `SafeNote.computeHash` 定义。**未改动任何 hash 定义**，blob id / AAD / 存量数据零影响，无需迁移。。
