## release.py 增强：产出 Windows/Android zip 压缩包 + SHA256 校验（2026-08-12 22:55 GMT+8）

### 需求
公开 GitHub Release 只发布 Windows 与 Android 二进制**压缩包**；原 `scripts/release.py` 仅复制单个 `safenotes.exe`（缺 DLL 与 `data/` 无法运行），且无任何 zip 打包。

### 改动（scripts/release.py 重写）
- **路径锚定**：所有产物路径改用 `ROOT`（脚本所在目录上级）锚定，`subprocess` 替代 `os.system`，任一构建失败即终止（check=True）。
- **Windows zip**：`zip_windows()` 把整个 `build/windows/x64/runner/Release/` 打包为 `safenotes-<version>-windows-x64.zip`（exe + 5 个 DLL + `data/` 26M），排除运行时生成的 `logs/`。
- **Android zip**：`zip_android()` 把 3 个 split-per-abi APK + fat APK + metadata 汇总为 `safenotes-<version>-android.zip`（单独 APK 仍保留在 release 目录，可单独上传）。
- **SHA256SUMS.txt**：`write_sha256()` 为全部 zip/apk/json 产物生成校验清单。
- **去掉 AAB/playstore**：本 fork 仅通过 GitHub Release 发布，不再构建 AppBundle（省一次 `flutter clean` + `appbundle` 构建）。
- **构建节奏**：`flutter clean && flutter pub get` 只在开头执行一次，之后连续构建 split-per-abi → fat APK → Windows，减少重复 clean。
- 脚本末尾打印 `gh release create` 发布命令示例。

### 验证
- `python -m py_compile` 通过；用现有 `build/windows/x64/runner/Release/` 实测 `zip_windows`/`zip_android`/`write_sha256`：Windows zip 66 项、正确排除 `logs/`，sha256 清单生成正常（临时产物已清理，未触碰 `releases/`）。

## 登录被 WebDAV 初始化阻塞 30s + 登录页 setState-after-dispose 修复（2026-08-12 19:58 GMT+8）

### 现象（用户局域网 WebDAV 出门后复现）
1. 局域网 WebDAV 服务器不可达时，登录后卡在 verifying 约 30 秒才进主界面；
   期间日志 `BackendUnavailableException: MKCOL network error: TimeoutException after 0:00:30.000000`，
   且后台 autoSync 每轮重试仍各等 30s（"后端未就绪，尝试重新初始化"循环）。
2. 会话超时锁定登出瞬间触发未捕获异常：
   `setState() called after dispose(): EncryptionPhraseLoginPageState`（login.dart:116）。

### 根因
1. `_onLoginSuccess`（lib/views/authentication/login.dart）**await `SyncService.initBackend`**，
   而 WebDAV `_mkcol` 统一 HTTP 超时 `_httpTimeout = 30s`（packages/core/.../webdav_backend.dart:82），
   网络不可达时登录流程被整段阻塞 30s（日志 19:34:18 登录成功 → 19:34:48 才进主界面）。
2. 登录页 initState 里 `auth.isDeviceSupported().then(...)` 直接 `setState()` 未检查 `mounted`，
   页面在检测完成前被销毁（锁定登出切换路由）即触发 setState-after-dispose。

### 改动
- `lib/views/authentication/login.dart` `_onLoginSuccess`：
  `initBackend` 由 await 改为 `unawaited(...)` 后台执行（fire-and-forget）——
  登录路径绝不被网络等待阻塞；初始化成功后再触发 `autoSync` 首次同步，
  失败仅 `Log.sync.w` 记日志，由主界面同步状态 UI 展示"后端未就绪"，本地笔记立即可用。
  移除原失败 snackbar（页面即将切换，旧 context 有失效风险）。
- `lib/views/authentication/login.dart` initState：
  `auth.isDeviceSupported().then` 回调加 `if (!mounted) return;`（修复 setState-after-dispose）。
- `packages/core/lib/src/sync/backends/webdav_backend.dart`：
  `_httpTimeout` 30s → 15s（同步载荷均为笔记小文件，15s 充足；后端不可达时判定更快、
  后台重试平滑，避免每轮失败都"卡 30s"的观感）。
  （注：20:02 已进一步改为"数据 30s / 探测 8s"分层方案，见上方章节，15s 版本已废弃。）

## 调试面板把索引当表查询修复：no such table: idx_notes_*（2026-08-12 19:28 GMT+8）

### 现象
- 日志反复刷屏（每次打开调试面板 DB 页出现 3 条）：
  `E/SQLiteLog: (1) no such table: idx_notes_uuid in "SELECT * FROM "idx_notes_uuid" LIMIT ?"`（idx_notes_deleted / idx_notes_synced 同理）。

### 根因（非数据丢失：safe_notes / sync_meta 表及三个索引都建得好好的）
- `idx_notes_uuid` 等三个对象是 `safe_notes` 表上的**索引（INDEX）**，SQLite 不允许 `SELECT * FROM <索引>`（报 no such table）。
- `NotesDatabase.inspectMetadata()` 从 `sqlite_master` 列出 `type IN ('table','view','index','trigger')` 全部对象；
  前端 `assets/web/dashboard.html` 的 `loadDb()` 对**每个**对象无条件调用 `loadTableData(t.name)`，
  于是索引名被当成表名请求 `/api/db?table=idx_notes_uuid`。
- 后端 `_serveDbInspect` 透传 table 参数给 `queryTableRows()`，后者只做标识符白名单校验（索引名是合法标识符，通过），
  执行 `SELECT * FROM "idx_notes_uuid"` → SQLite 原生报 no such table，刷屏。

### 改动（两层防御）
- 前端根因 `assets/web/dashboard.html`：`loadDb()` 仅对 `type==='table'||type==='view'` 的对象创建数据区并加载行数据；
  索引/触发器卡片只显示名称与类型，不再发查询请求（杜绝刷屏）。
- 后端防御 `packages/core/lib/src/db/database_handler.dart` `queryTableRows()`：查询前先查 `sqlite_master` 校验对象类型，
  非 表/视图 抛语义化 `ArgumentError`（`xx 是 index 类型，不是表/视图`），对象不存在也报明确错误；
  即使外部/手工直接请求 `?table=idx_notes_uuid` 也返回友好错误而非 SQLite 原生报错。

### 验证
- `flutter analyze` No issues；`flutter build windows --debug` 成功；`flutter run -d windows` 冒烟启动到登录页无崩溃（DB version=4 打开正常，进程已随管道退出清理）。

## 页面切换黑屏修复：移动端改用平台默认转场（2026-08-12 18:31 GMT+8）

### 背景
- 用户反馈：手机端点开笔记/进入设置等所有 pushNamed 页面切换瞬间短暂黑屏。
- 根因：commit `9ac2664` 引入的自定义 `FadeThroughRoute`（lib/routes/route_generator.dart）设 `opaque: false` + 交叉淡入淡出（旧页前 60% 淡出、新页后 60% 淡入），动画约 40%~60% 区间两层同时接近全透明；全路由均非 opaque → Overlay 底层无任何不透明背景，直接透出引擎视图黑色背景，每次切换黑闪约 80ms（返回同样发生）。
- 佐证：旧版 `PageTransition(leftToRight)` 默认 opaque:true（旧页垫底）不黑屏；官方 `FadeForwardsPageTransitionsBuilder`（Flutter 3.44 SDK page_transitions_theme.dart）在交叉淡出期间显式 `ColoredBox(color: surface)` 垫背景（注释原文 "avoids a black background between two pages"）→ 非框架 bug，属自研转场实现缺陷。

### 改动（lib/routes/route_generator.dart）
- 移动端（Android/iOS）`_buildRoute` 由 `FadeThroughRoute` 改为 `MaterialPageRoute`：走 Flutter 默认 `pageTransitionsTheme`（Android = FadeForwards/预测性返回手势，iOS = Cupertino 滑动 + 边缘返回），符合官方 M3 推荐 forward/backward 用平台默认、随平台更新自动演进。
- 删除不再使用的 `FadeThroughRoute` 类（-56 行）。
- 桌面端保留 `PageTransition(fade, 250ms)`（Windows Fluent 风格，无黑屏问题）。
